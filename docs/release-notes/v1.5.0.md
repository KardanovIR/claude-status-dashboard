The board looks like an instrument now, not a dashboard template — and two
long-standing lies in the status vocabulary are fixed.

## The board has a design system

It had none: fourteen flat hex tokens, no spacing, radius, shadow, duration or
typography scale, eleven different border-radii, and six status colours that were
unmodified Tailwind defaults on a near-black ground. That is the generic AI
dashboard look, and this replaces the palette's **basis**, not its shades.

Everything is OKLCH, so a tint is derived rather than typed — the old stylesheet
carried twelve hand-written rgba tints that had already drifted from the colours
they came from.

Colour is ranked by **who is waiting**, not by lifecycle stage. `blocked` and
`done` — the two states that need a human — carry the chroma; planning, coding and
testing recede. Ranking by stage put the brightest colour on `coding`, the most
common state, and the dimmest on the ones that actually need you.

Each card's surface is tinted by its state, 10% (14% for `blocked`). That number
is solved, not chosen: at 6% the meta line fell to 4.01:1 and failed WCAG AA, so
tertiary text was lifted to 64.5% lightness, which bought the headroom to tint
harder. The worst contrast ratio anywhere on the board is now 4.53:1, and all nine
colours were checked against every tinted surface rather than asserted.

Type is Barlow, self-hosted — 140 KB of woff2 in `public/fonts`, not a CDN link,
because `docs/privacy.md` promises no third-party requests and a Google webfont is
one on every view.

The reasoning, including five directions rejected and why, is in `.impeccable.md`.

## iOS caught up, and lost a bug on the way

The iOS card carried both things the web redesign removed — a 4pt coloured stripe
and a glow on `blocked` — and `Theme.swift` is now the web's token set, converted
from OKLCH once with the original written beside each value.

The card used to be made tappable by an invisible full-card `NavigationLink`
overlay that sat **on top of** the Focus and Resume controls and could swallow a
tap meant for them. Opening history is the card's own tap now, on its content
rather than the whole card, so it cannot reach across the divider. That leaves one
real control, which can afford a real affordance: its own surface, a hairline, a
44pt target.

Also gone: a badge that pulsed forever on every active card — ambient animation
that reported nothing, never stopped, and cost battery on a board left open all
day. Only staleness dims a card now; `done` used to be dimmed to 55% from when it
meant "nothing to see", which hid the state the board most needs to surface.

**Reduce Motion is honoured.** The app claimed to and never did.

## `done` is a real status now

`Stop` emits `done` / "Turn finished" instead of `idle` / "Waiting for input".
`done` was declared by the server, styled by all three clients, and never once
sent — while `idle` folded two unrelated situations into one word: a session
nobody has asked anything of yet, and a session whose answer is on screen waiting
to be read. `SessionStart` is now the only `idle`.

> **Upgrade note.** `src/push.ts` has always had a `done` push behind the
> `notify_done` opt-in, and it has never fired, because `done` never arrived. It
> lights up with this release — at the end of **every turn**, not every session.
> The 60-second debounce bounds a burst, not a normal back-and-forth. Turn it off
> in the app if that is more than you want.

## Cards stop renaming themselves

A card's `name` is pinned at the session's first event. It used to be recomputed
from the working directory on every event, so a session that changed directory
renamed its own card — one session read "backend" and later "docs" on the owner's
own board.

`project` deliberately still follows the live directory: token spend is aggregated
per project folder per day across sessions, so a session that really moved really
did spend tokens in both places. The two fields now diverge exactly when a session
moves, which is the only time the difference is worth showing.

## Tokens per session, not just per project

The usage detail screen could say which project burned the quota but not which
session, so two agents in one repo were indistinguishable. Both are reported now.

## Focus

- One key press per agent, instead of one per session.
- Honest `mux-detached`: a tmux or screen session with no attached client says so
  rather than claiming it raised a window.
- Warp gets its own session focus rather than only its window.
- The Focus control moved into a rail, and the meta line degrades instead of
  breaking when a field is missing.

## Known gap

**Android still has the old palette.** Web, iOS and the design tokens agree;
Android does not, and was not ported in this release.

## Also in this release

- Deletion is soft throughout: a deleted board keeps its host record, and the
  terms say what that means.
- Docs corrected rather than updated — a plan-usage bar belongs to
  (board, agent, window) and never to a card, and the window the API calls
  `session` is the plan's 5-hour rolling window, not the agent session. Both
  `hooks.md` and `api.md` implied otherwise. An event table that rendered as
  literal text on agstatus.online/docs is fixed.
- CI runs the CLI suite on Linux honestly — 29 of 369 tests were failing on Ubuntu
  purely on fixtures that had encoded the machine they were written on — and a new
  macOS job gives `install`, `doctor` and the resume launcher their first coverage
  on the platform they ship to.
- The secret scanner knows a key from a test vector, with a deliberately narrow
  path-scoped allowlist, verified by planting real credential shapes and
  confirming they still trip it.
