Two in three Codex notifications were for nothing. And the web board finally
looks like the rest of the product.

## Codex only says `blocked` when a human is actually being asked

Codex fires its `PermissionRequest` hook when the **model asks to escalate** —
not when **you** are asked. The hook took it at face value and mapped it
straight to `blocked`, which is the push trigger. Most escalations never reach
a person: Codex answers them itself.

Counted over the 2,097 turns in one real `~/.codex/sessions`, **1,418 were
answered automatically**. Roughly two notifications in three were for work that
never paused. It was caught by watching a live board: Codex requested an
escalation, the card went red and pushed, and Codex carried straight on to
running tests. Nobody had been asked anything.

The hook now reads `approvals_reviewer` from the session's own rollout log and
reports `blocked` only when the reviewer is `user`. An escalation Codex
approves itself posts **nothing at all** — the card keeps the status it had,
and the tool call that follows moves it on as usual.

> **`approval_policy` is not the field**, and it is the obvious wrong guess.
> Cross-tabulated over the same logs: 441 turns were `on-request` +
> `auto_review` (so gating on "not never" would not have caught the bug at all)
> and 433 were `never` + `user` (so gating on "never" would have **silenced 433
> requests a human was genuinely waiting on**). A notification that should not
> have come is noise; one that never comes defeats the product.

Three smaller things came out of the same investigation:

- **The session's rollout log is now found by `transcript_path`.** A rollout
  file is named by the *thread* id, which is not the `session_id` on the hook
  payload — of 226 logs on that machine, 181 disagreed. The old lookup found
  the right file about one time in five and fell through to a sibling the rest,
  which happened to be right for account-wide rate limits and is not good
  enough for anything that has to be about *this* session.
- **A blocked card shows the question that was actually asked.** Codex writes
  it out — "May I run the readiness tests in a fresh disposable PostgreSQL
  cluster?" — and it was already on stdin while the card said "Needs approval".
  `--minimal` still shows the generic label.
- **Unknown still means `blocked`.** Missing log, unattributable log, no turn
  context: all report exactly as before. Only a positive `auto_review`
  suppresses anything.

The reasoning, the counts and the three traps in reading the log are in
[docs/design/codex-approvals.md](../design/codex-approvals.md), because this
had been diagnosed and lost once already.

## The web board is on the design system it has been serving since 1.5

1.5 shipped `tokens.css` and `board.css` and **nothing loaded them** — the
design commit was additive only and never touched `index.html`. The 1.5 notes
had to carry a blockquote admitting it. That is fixed, along with the landing,
docs and privacy pages, which each carried their own hand-typed copy of the
same fourteen hex values.

All four surfaces now read one palette. The card itself was split into
`card.css` so the landing page renders the **real** component instead of a
simulation of it — the old simulation had already drifted, still painting a 3px
coloured edge stripe that `board.css` says in so many words the card tint
exists *instead of*.

Also: ten status and agent marks, so state is not carried by colour alone;
`prefers-reduced-motion` honoured; the two animations that looped forever are
gone; and the grid is reconciled by key, so a frame about one card no longer
restarts every other card's animation and drops your keyboard focus.

## Fixes

- **A machine name could render four pixels wide.** Every item in a card's meta
  line is fixed-width except the machine and project names, so on a narrow card
  they absorbed the entire shortfall — the text was still in the DOM and still
  read aloud by a screen reader, so it looked missing and measured present. The
  line wraps now.
- **The plan-limit blocks were invisible to screen readers.** They carried
  `role="button"`, which makes every descendant presentational, so the whole
  readout was replaced by a single label. They have a real button inside them
  now and the percentages are readable again. Keyboard focus also survives
  opening and closing the usage detail, which previously dropped it to the top
  of the document.
- **The install one-liner was clipped on a phone.** A `1fr` grid track will not
  shrink below its content, so the command — the one you pipe into a shell —
  lost its right-hand end.
- Navigation links on the docs, landing and privacy pages are touch-sized where
  there is no hover; the docs table of contents is the page's primary
  navigation on a phone and its links were 24px.

## Corrections to the privacy policy

Found by auditing it against the code rather than against the previous version:

- It said Focus's local records are **removed when the listener is
  uninstalled**. They are not: a plain uninstall leaves them and says so on
  screen, and `agstatus uninstall` does not accept `--purge` at all. The policy
  now says what actually happens.
- It said Focus is **off by default**. The install command quoted on the same
  page installs it by default on macOS; `--no-focus` is the opt-out.
- It said token totals are kept **90 days**. That is true of plan-usage history
  and per-project totals; the per-session totals are kept 7 days.
- It claimed the listener "ships in a later release" — it shipped on
  23 September — and still gave `npx agstatus init` as the setup command, which
  resolves to 1.3.0, a build whose data footprint is not the one described.
- It never mentioned that the server mints **pairing codes** and holds them,
  mapped to your board token, for fifteen minutes. That was the one outright
  omission about server-side data.
- It now covers the Android client in the repository, and scopes push to iOS.

`docs/privacy.md` is re-synced with it: the two had drifted a month apart, and
that file is linked from the README and from inside the iOS app.

## Not in this release

**iOS and Android are unchanged.** iOS 1.5.0 is in review and keeps its version;
the Android client is still not published anywhere. The Codex fix reaches a
machine when you re-run the installer:

```bash
curl -fsSL https://agstatus.online/install.sh | sh
```

It is the same command for a first install and an upgrade, and it keeps the
board you already have.
