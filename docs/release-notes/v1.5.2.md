Two fixes you can see, and the rest of the web caught up with the design
system it has been serving since 1.5.

## Codex Desktop sessions had UUIDs for names

Cards titled `01a10b09-b1ee-7501-95b4-d0ebf7acad5e`. Only ever Codex Desktop,
never the CLI, and the reason is that macOS starts a GUI app in `/`: the
basename of that is empty, so the hook sent no name and the server's
last-resort fallback is the session id.

A session with no project folder is named after its agent now — **Codex** — and
so is one whose folder is a bare UUID, which happens because Codex writes
scratch workspaces under `.codex/visualizations/<date>/<uuid>`. The placeholder
is not pinned, so the first event that does know its folder still claims the
card.

## The installer stopped crying wolf about `/hooks`

Codex trusts a hook by hashing its command string, so only a **changed**
command invalidates that trust. The installer said "this release changed that
command" on every single run, whether it had or not — so a reinstall whose
command was byte-identical still sent you off to re-trust a hook that was never
untrusted.

It compares now. Nothing registered yet still asks for `/hooks`, because Codex
will not run a hook it has not been told to trust; the same command says
nothing; a genuinely changed one says so, and means it.

## The rest of the review

1.5.1 shipped the three public pages on the design system. An adversarial
review of that work raised 56 findings and confirmed 35; 1.5.1 fixed the false
claims, and this release works through the remaining 23.

**The demo board was still a copy.** `card.css` was split out so the landing
page could render the real card — but the page kept its own grid at a 250px
minimum, 70px under the floor the board uses, and had reimplemented the
plan-limit block as a near-copy that had already drifted four ways. Both are
the shared component now, so the picture cannot promise something the product
does not do. The block no longer offers a pointer and a hover lift where there
is nothing to click.

**Accessibility.** The board shipped with no `h1`, and so did the generated
docs page — while the generator's own comment claimed it supplied one. The
connection state was colour alone in an unnamed span; it is announced now, and
the dot goes hollow when the stream is down. The install tabs declared
`role="tab"` and implemented none of the pattern. Neither copy button announced
success. The demo board auto-updated forever with no way to stop it, which is a
Level A failure; it has a pause control.

**Type.** `h3` and `h4` were one pixel apart below 1062px and `h4` was the size
of body text. Measuring the fix caught the same fault between `h1` and `h2` on
the docs page. The scale is distinct at every width now.

**Honesty.** The Limits card implied per-model caps were Codex-only; the
History card promised a timeline the web board does not have; three screenshot
alt texts described fields the images do not contain. Six feature cards wore
state colours and state marks as decoration — the testing beaker on "Limits" —
which spends the board's state vocabulary on things that are not states. They
have their own marks, and only Blocked keeps a colour.

**Stale.** The README's hero was the pre-rename "Claude Sessions" board from
April and its iOS shots were from July; all four are recaptured. Its feature
list gained the four shipped surfaces it never mentioned, and its project
layout gained the native Android client it omitted entirely.

## Upgrading

```bash
curl -fsSL https://agstatus.online/install.sh | sh
```

Same command for a first install and an upgrade, and it keeps the board you
already have. iOS and Android are unchanged: iOS 1.5.0 is in review, and the
Android client is still not published anywhere.
