Two of the known gaps 1.5.0 wrote down, closed.

## `agstatus version`

The CLI could not tell you which version it was. 1.5.0 listed this as a known
gap — *"The installed artifact's package.json is the only place the number
appears"* — and `release.yml` had been worse than silent about it: its
version-guard comment cited `agstatus --version` as the thing a mistagged
release would make disagree with the artifact's name, for a command that did
not exist.

```console
$ agstatus version
agstatus 1.5.3
```

`agstatus --version` and `agstatus -v` do the same. One line, so a script can
split it on the space, and it reads the number out of the `package.json`
shipped beside the binary rather than one baked in at build time — a
hand-patched install reports what is actually on disk. A version query is the
command you run when something else has already gone wrong, so an unreadable
package.json gets you `agstatus unknown` and exit 0 rather than a stack trace.

## The Homebrew tap is archived

[`KardanovIR/homebrew-tap`](https://github.com/KardanovIR/homebrew-tap) is
read-only now. Its README said the formula was *"updated automatically by the
main repo's release workflow on every v\* tag"*, which stopped being true when
npm and Homebrew were retired as channels — this repo's own `release.yml` says
as much in a comment. So anyone arriving at the tap was told they were getting
current AgStatus and handed a build from before Focus, the usage screens and
the 1.5 redesign, with nothing to indicate anything was missing.

**Nothing breaks.** The formula still resolves to `agstatus@1.3.0` on npm, so
an existing `brew install kardanovir/tap/agstatus` in a script still succeeds —
it just installs 1.3.0, and the tap's front page now says so before you run it
and points at the installer instead.

To move a machine off the Homebrew copy:

```bash
brew uninstall agstatus && brew untap kardanovir/tap
curl -fsSL https://agstatus.online/install.sh | sh
```

## Still open

Of 1.5.0's known gaps, the web board and the public pages were done in 1.5.1
and 1.5.2, and these two close here. What remains is **Android**: it still
wears the old palette, it is still not published to any store, and CI still
does not build it. The Windows installer is parse-checked in CI but never
executed.
